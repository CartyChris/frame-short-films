# Frame 7 studio guide

Frame keeps films and attachments on the device where you work. Export a complete project backup when moving between devices or before clearing browser data. An imported backup becomes a separate project. The first-launch sample is optional and stays separate from a blank film.

## Start in Chat

Describe the film in your own words. Use **+**, drag files onto Chat, or type **@** to select files already saved with the film. Review and edit the shot outline, or choose auto-proceed after the director has asked its remaining questions. The selected model must be connected for generation.

Original attachments are stored locally. Bounded excerpts of supported text files are sent to the director; other file contents are not automatically understood. If an OpenRouter connection and a vision-capable model are selected, you may explicitly choose to send up to three PNG, JPEG, or WebP originals, totaling 750 KiB. Their metadata is included. Other providers and file types currently use text or metadata only. A provider can reject a model or image even if it is selected.

In Produce, assign connected models and optional instructions to the director, character designer, animator, editor, and composer. These roles run in sequence. A connected MCP server can be enabled for selected tools; one tool can be called or skipped during the production's tool step. An uncertain tool operation stays blocked rather than being sent again. External Blender changes must still be brought back through the Blender exchange.

## ComfyUI and generation services

In Studios → Production tools → ComfyUI, connect a separately running local ComfyUI through the local companion. You can open its own editor, submit an API-format workflow, check saved job IDs, and import supported output. Its own Manager and installed nodes remain in that separate installation. An embedded editor can be blocked by the browser or server; use its new-tab link if needed. Frame does not install ComfyUI, nodes, or model weights.

The Freefield panel connects to a separately running local [Freefield](https://github.com/neuregex/freefield) server, displays available manifest-driven workflows, retains selected inputs, tracks runs, and imports supported image, audio, and video results. For a remote server, use a user-managed local tunnel. Freefield may retain uploaded files and prompts in its own history. Freefield's MIT code and individual model weights have separate license terms; check each workflow's requirements. Uploads are limited to eight files and 100 MiB in total; temporary processing may use two to three times that amount of memory. A lost submission response may require checking Freefield history manually.

The Comfy Cloud panel supports the documented Comfy API v2 on Comfy Cloud and official deployment hosts. A paid plan or credits may be required. It saves job IDs and shows status and output metadata; cloud-output downloading is not yet implemented in Frame. See the [Comfy API v2 overview](https://docs.comfy.org/api-reference/v2/overview) and [Comfy Cloud API overview](https://docs.comfy.org/development/cloud/overview).

The Higgsfield Cloud panel supports the six models listed in the panel using separate Cloud API credentials. Image-to-video currently accepts a public HTTPS reference URL; file upload and automatic result import are not implemented. Provider links, reference URLs, prompts and settings are included in project backups; signed links may grant access to anyone holding the backup. Consumer subscription/OAuth access is not established. The [higgsfield-ai/higgsfield](https://github.com/higgsfield-ai/higgsfield) repository is a distributed GPU training framework, not the complete hosted creative product; the separate [official client](https://github.com/higgsfield-ai/higgsfield-client) documents its Cloud API.

## Recover work

Films and media removed from the main library appear in Recovery. Restoring is reversible; permanent deletion requires a second confirmation and is blocked if saved work still uses an item. Exported files and Mac disk backups are separate copies. Active generations are protected between supported browser tabs; for older drafts or browsers without Web Locks, stop the generation and close other Frame tabs before explicitly recovering a draft. Project backups preserve original attachments, saved draft chunks, workflow settings and operation histories. Imported tool histories are read-only and cannot grant a new dispatch permission.

## Limits

A model-generated film still needs review. Not every provider supports every media type, long-form consistency, or every external tool. The local companion and installed services are required for local MCP, ComfyUI, and Freefield from the web app; a hosted frontend does not run the user's GPU. Tests using simulated providers do not establish real account, model, hardware, or billing availability.

## Local Vork rendering

In 3D studio, **Render with local Vork** uses a separately installed Vork renderer on the same computer through the paired companion. The renderer itself selects its supported Metal or Vulkan backend. You can render the current Frame shot to PNG or MP4, check its saved job ID after leaving the panel, and import a completed output into Media. Frame keeps the source scene and local job files; a completed job can be explicitly deleted. Vork output imports are limited to 256 MiB; larger outputs remain in the local job folder. Frame's own HTML titles, audio, point particles, screen effects and changing camera field of view are not part of the GLB interchange. Review materials, lighting and animation in the result.

Alternatively, select a ZIP containing a Vork JSON scene, Slang programs and their referenced files. Frame preserves its original ZIP with the project, lets you edit JSON and Slang text, and includes those edits in a complete project backup. Packages are limited to 500 files and 100 MiB; edited text is limited to 2 MiB in total. The exact scene and programs are run by your separately installed Vork, under your account's permissions, after you explicitly confirm that you trust them. They may access local resources available to that process and consume substantial GPU time or disk space. The web/PWA connects to a companion on the same computer; it does not run Vork on Vercel. Vork's preview license restricts hosted rendering and modified redistribution; see [Vork and its license](https://github.com/voyager-so/vork).

## Local models and creative library

Select **Ollama** in Connections and pair the local companion to list models already installed at `127.0.0.1:11434`. No model is downloaded automatically. Select a chat-capable model; embedding-only models cannot generate a film. The reasoning selector requests the model's default, on, or off mode where supported. Codex, Claude Code and other supported CLI profiles use their own local sign-in. Other trusted CLIs can be registered with an explicitly reviewed executable and fixed arguments; this does not guarantee that every CLI implements the necessary text or streaming protocol.

Open **Creative library** from Chat to reuse locally saved styles, character models and scenes, and to approve, edit, remove, import or export golden references and artistic preferences. Saved project names, styles, character names and scene titles are indexed locally. When the library's context switch is on, relevant short notes and matching saved-film descriptions are sent to the selected model provider; original image and 3D files are not sent automatically. The switch can be turned off. Golden notes are retrieval guidance, not a trained or fine-tuned model; their quality still depends on human review. Exported notes contain reference IDs rather than the underlying films or media, so keep complete project backups as well. Copying a scene creates editable copies of its linked models and cast; check continuity and re-bake physics if requested.

Casting's resting-arm controls adjust its guided 2D puppet. Its walking, talking and dancing previews are animation presets, not a 2D collision simulator. Detailed realism depends on the selected assets, models, renderer and direction; no renderer or provider can guarantee a perfect or fully consistent film.

## Cascadeur animation exchange

The 3D studio's **Cascadeur animation exchange** exports the current shot as an animated GLB. Open it in Cascadeur 2025.1 or newer, animate or adjust the model there, then export an uncompressed GLB including animations. To replace one object in the current shot, export only that character from Cascadeur, select its matching object in Frame and use **Import and replace selected object**. Frame retains the original model and selects the first returned clip. If the selected object changed while the file was importing, the returned model is saved to the library without replacing that object. With no object selected, the returned model is simply added to the library. Inspect scale, rig, materials, animation, camera and timing after exchange; editable Cascadeur controls and Frame's film effects are not reconstructed. Frame's AI can stage its own 3D shot before export; this exchange does not execute AI commands inside Cascadeur. Cascadeur is separately installed and licensed. This exchange has not been verified against a live Cascadeur installation on this machine.

Official guides: https://cascadeur.com/help/category/282 and https://cascadeur.com/help/category/283. Older versions may require FBX instead. Cascadeur's embedded Python console and supported scripting API are separate from Frame and require a locally configured, explicitly reviewed integration.

### Connect a reviewed Cascadeur MCP bridge

Frame can launch a **separately installed local stdio MCP server** through its paired companion. In Studios → Local tools, choose **Reviewed local MCP executable**, load or create a profile, and enter the server's absolute executable path and fixed arguments as a JSON array. Read the exact command and review the program before checking the trust box. The local program runs with the user's normal file and network privileges; do not place credentials in its arguments. Profiles remain on the companion computer and are not embedded in film backups. Editing or removing a profile invalidates its existing connection and production grant.

For example, the independent [Cascadeur MCP bridge](https://github.com/gprethesh/cascadeur-mcp) documents an installed Python virtual environment, a private bridge directory and a workspace, plus a startup script that must be run inside Cascadeur. Use the bridge's generated executable and argument list in the reviewed profile. This bridge is not made by Cascadeur or Frame, is not bundled, and has not been tested with Cascadeur on this machine. The bridge's own guide describes its compatibility and permissions. The official Cascadeur **Scripts → MCP → Start script server** is a different interface; do not point Frame's Streamable HTTP MCP option at an unverified raw script endpoint.

After connecting, a model can draft a tool call for your review in Local tools; in Produce, you can explicitly enable selected tools for one production. Current production makes at most one permitted external tool call per run, and external edits are not imported automatically. Use the Cascadeur file exchange to bring a saved model back, and inspect its timing, rig and appearance. An interrupted tool request can have an unknown outcome; inspect the saved receipt and the target application before taking further action.
